# StackWise: orientation for Claude sessions

Planning tool for beginners building web apps with AI builders. A deterministic rules engine checks every connection in a stack against sourced facts, ranks what works, and exports a spec pack. Optional Claude features read descriptions, explain plans and keep facts fresh. Next.js 16 + React 19 + React Flow 12, TypeScript, Zod 4, Vitest 4, Anthropic SDK 0.125, pnpm 12. Styles come from Michael's mk-ui (`src/styles/mk-ui.css`, copied from `Projects/mk-ui`), re-themed to an Apple look by `src/styles/theme-apple.css` (system font, glass, light and dark from the system).

## Commands

- `pnpm dev` runs on port 4310 (hub launch config name: `stackwise`)
- `pnpm test`, `pnpm check:data`, `pnpm typecheck`, `pnpm lint`, `pnpm build`
- `pnpm check:options -- --id <id,id>` checks single option files without loading the catalog (safe while others write data)
- `pnpm eval:prefill`, `pnpm eval:plain-llm`, `pnpm check:sources [--apply]`, `pnpm draft:option -- ...` (these call Claude; they read `.env.local`)
- `pnpm build:logos [-- --only <id,id>]` downloads logos into `public/logos` (network, no key)
- `stackwise [folder]` (from `bin/stackwise`, installed with `pnpm link --global`; or `pnpm stackwise -- <folder>`) starts StackWise in the background if it isn't up (log and pid in `.stackwise/`) and opens `#open=<folder>`; `stackwise setup` adds the MCP server to Claude Code; `stackwise stop` stops it
- `pnpm mcp` runs StackWise's MCP server over stdio; the app serves the same tools at `/api/mcp` (docs/MCP.md)

## Map

- `data/` is the product's knowledge. `src/engine/load.ts` parses it with `schema.ts`; `integrity.ts` holds the cross-file checks `data.test.ts` enforces.
- `src/engine/talk.ts` builds the brief for talking one part through (connection, setup, checks, cost, facts, alternatives with verdicts, the note), answers from it without Claude (`answerFromFacts`), and drafts notes. `src/ai/talk.ts` asks Claude with that brief; `src/app/api/talk` falls back to the facts. `src/components/AskPanel.tsx` is the one place to talk to AI: one conversation per plan (Cmd+K, double-click, right-click "Ask about this"), with an Answering menu that sends each message to a terminal agent, the Claude API, or StackWise's facts. `NoteEditor.tsx` is the note, in Details and in a connection.
- `src/engine/wiring.ts` turns a stack into connections and the environment variables that travel along each one (names, where each value comes from, whether the browser can read it), plus the `.env` file text. It never holds a value.
- `src/engine/evaluate.ts` produces verdicts. `score.ts` ranks and searches (branch and bound, tested against brute force; domains rank on first-year and renewal price, payments on the fee from a $20 sale). `cost.ts` adds yearly and one-time costs (domains, `planning.json` `fees`) and counts a shared plan once (`shared_plans`, or one option in two parts). `followups.ts` picks questions. `stats.ts` turns facts into the stats on cards, nodes, Details, Compare and the strip above the canvas. `cost.ts`, `spec.ts`, `checklist.ts`, `decisions.ts`, `share.ts`, `staleness.ts`, `summary.ts`, `prefill.ts` do what their names say.
- `data/logos.json` says where each logo comes from (Simple Icons slug or the service's site); `scripts/logos.ts` fetches them into `public/logos/`, which is committed. `Logo` in `src/components/ui.tsx` falls back to a letter if a file is missing.
- `src/ai/` is server-only: `config.ts` (model, client, errors), `providers.ts` (the registry of built-in AIs: Claude, OpenAI, Gemini, and OpenAI-compatible presets for OpenRouter, Groq, Mistral, Ollama and a custom endpoint; adding a model is one entry; presets without a default model stay off until their model variable is set; answers are checked against the same Zod schemas), `prefill.ts`, `explain.ts`, `talk.ts` (each has a Claude path and a `provider*` path), `rate-limit.ts`. Routes in `src/app/api/` take an optional `provider`, pick the first with a key (Claude first) when it's left out, and always fall back to keywords or a template.
- `src/components/store.ts` is all plan state as a pure reducer (plans, undo/redo, import, migration from v1); `usePlans.ts` wires it to the engine. `answerers.ts` is the one list of who can answer (terminal agents, built-in AIs, StackWise facts), read by `ConnectPanel.tsx` (the first screen and the connection pill in the top bar), and `AskPanel.tsx`. `templates.ts` holds the starting points by kind of app (web, iOS, Android, both, AI, store, internal tool), applied with `applyTemplate`. `AddPart.tsx` is the n8n-style picker (A key, the + in the dock and on the app card). `Workspace.tsx` puts the canvas full screen and floats everything over it: the top bar, the dock, one left panel (Overview, Parts, Checklist, Learn), Details on the right, the planner sheet, the Ask panel, and the right-click menus (built there, rendered by `ContextMenu.tsx`).
- `src/app/api/local/route.ts` writes a project into a folder on this computer; `src/mcp/localfiles.ts` holds the rules it follows (which folders, which files it will not replace) and is tested without a file system.
- `src/mcp/` is the MCP server: `server.ts` (13 tools over the engine, plus the `pair` prompt), `pairing.ts` (agent ids, presence, wait settings, the pair instructions), `stdio.ts` (the command exported projects start), `registry.ts` (shared plans in `.stackwise/`, gitignored), `local.ts` (localhost-only guard). Routes: `src/app/api/mcp` (Streamable HTTP, stateless) and `src/app/api/pair` (the tab shares its plan, polls for agents' changes and messages, and posts your messages, via `usePairing.ts`). `src/engine/planops.ts` validates plan changes and builds reports; `src/engine/project.ts` builds the project pack (TASKS.md, agents, skills, `.mcp.json`).
- `src/project/` is a plan's linked project folder, server-side: `detect.ts` (what kind of project, how to run it, its health URL and Java version), `envfile.ts` (reading and setting env files as text, masking), `probes.ts` (one read-only GET per service, with an example of what travels), `sql.ts` (the read-only SQL rules and connection strings, including Spring's JDBC settings), `local.ts` (the file system, `fetch`, `pg`, `node:sqlite` and the processes StackWise starts). `git.ts` gives each extra agent its own git worktree (a sibling folder on a `stackwise/<agent>` branch), reports what each changed, and merges a branch back only into a clean main copy, backing out on conflict; tested against real throwaway repos in `git.test.ts`. All pure parts are tested in `project.test.ts`. `src/app/api/project` exposes it; `ProjectPanel.tsx` is the Project panel in the dock.
- `src/engine/merge.ts` merges two copies of a plan against the last copy both had (answers, parts and notes key by key); `stdio.ts` uses it so an agent editing `stackwise.plan.json` and the browser never overwrite each other.
- `scripts/` hold the evals, source checker, option drafter and logo fetcher; their pure parts (`eval-core.ts`, `source-check-core.ts`, the link ranking in `logos.ts`) are tested.

## Invariants, do not break

1. **The AI never decides compatibility.** Verdicts come from rules over facts. AI pre-fills answers (with quoted evidence that must exist in the description), explains a precomputed brief, or drafts facts for review.
2. **Unknown is never "works".** A missing fact makes a check "unknown". A null price means "no monthly plan" only on a `coverage: "full"` option.
3. **Product rules can only tighten.** Their schema has no "works" severity.
4. **Rules read at most two slots**, and only facts in that slot's `required_facts`. A `{ slot, filled }` condition checks emptiness without reading facts.
5. **Only product-rule notes are perks.** Capability-rule notes are neutral in scoring (`resultAdjustment`); a cost note once tipped storage toward the option with download fees.
6. **Every fact has a source URL, a date and a status.** New facts are `draft` until a person reviews them.
7. **No em dashes** in data, UI copy, generated files or docs. Code uses the `\u2014` escape when it has to mention one. The data, spec and AI tests check.
8. **Engine tests use fixtures** (`test-fixtures.ts`); only `data.test.ts` reads real data. AI tests use a fake client; nothing in the test suite calls the API.
9. **MCP tools only call the engine.** Claude asks StackWise; no tool lets it decide a verdict, price or limit. `update_plan` goes through `applyPlanUpdate`, the same validation as the planner.
10. **Default model is `claude-opus-5`** at low effort. OpenAI and Gemini are only used when someone picks them or they're the only key set with `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`). Don't swap models for cost without the owner asking.

## Gotchas

- mk-ui's reset sets `svg { max-width: 100% }`, which shrinks React Flow's edge SVGs to 0px so edges vanish. `globals.css` overrides it inside the canvas.
- The workspace renders client-only (`ClientRoot.tsx`, `ssr: false`) because state loads from localStorage.
- React Strict Mode runs effects twice in development. The share-link import clears the hash first and remembers its token, or it imports the plan twice.
- `page.tsx` is `force-dynamic` so edits to `data/` show up on refresh.
- Browser screenshots in the preview pane can lag a render, and the console buffer keeps errors from earlier hot reloads. Verify state with `javascript_tool` after a reload.
- In the preview browser, clipboard writes fail because the document isn't focused; the share action falls back to showing the link in the toast.
- `pnpm` scripts that call Claude use `tsx --env-file-if-exists=.env.local`, which needs Node 22.9 or newer.
- Site favicons vary: some are white marks meant for dark browser tabs (the fetcher skips `prefers-color-scheme: dark` links), some are wordmarks too small to read. After `build:logos`, look at the palette; switch a bad one to a Simple Icons slug.
- The search's bound must stay tight. Counting shared accounts only at the leaf let four new parts push the all-yes plan to 25 seconds; they're counted incrementally now. `data.test.ts` fails if that plan takes over 1.5 seconds, so run it after adding parts or options.
- Some sites answer a missing icon URL with an HTML page and a 200. The logo fetcher trusts file bytes (`sniffImage`), not names or content types.
- The stdio MCP server must never write to stdout except JSON-RPC; log to stderr. `.mcp.json` runs it with `pnpm --silent --dir <StackWise>` so the process starts in StackWise's folder, and Claude Code passes the project in `CLAUDE_PROJECT_DIR`.
- `/api/mcp` and `/api/pair` refuse non-local Host and Origin headers. Test them with `curl` against localhost, or the SDK's `StreamableHTTPClientTransport`.
- The canvas fits only after React Flow has measured every node (`AutoFit` reads the store) and never zooms past 100%. Fitting on `useNodesInitialized` alone ran before new nodes had sizes and left the canvas zoomed in on the old ones. Parts are spaced evenly among the visible ones, on an ellipse that grows with their count, until someone moves them.
- Node positions are middles (`nodeOrigin={[0.5, 0.5]}`), but React Flow hands back the top left corner in `onNodeDragStop`, so `land()` adds half the measured size. Without that every part hops up and left by half its size as it lands. Controls inside a node need `nodrag` (and `nowheel` for anything that scrolls) or pressing them starts a drag.
- Moving a part and tidying up are not undoable, like checking a box: undo stays about the plan. `plan.layout` is per plan, lives only in the browser, and is not in `SharedPlan`, so Claude can't move things.
- Two-way agent chat: messages live in the shared plan record (`.stackwise/plans/<id>.json`, `messages` and `agents`), not in the browser store. `wait_for_message` polls the file every second for up to 4 minutes; `/api/mcp` stays in JSON response mode, so the HTTP request just stays open (progress pings only reach stdio clients). A wait records a `waitId`, and an older call for the same agent gives up without taking messages once a newer one starts. Test it with `curl` against `/api/mcp` (`tools/call` works without `initialize` in stateless mode).
- The built-in AI's conversation is one per plan (`plan.chat`, each turn tagged `about`), migrated from the old per-part `threads`. `/api/talk` gets only the last 20 turns about the same part. `factsOnly` on `/api/talk` and `/api/explain` makes "StackWise facts" in the Answering menu skip Claude even with a key.
- Notes are part of `SharedPlan` (`notes`, defaulting to `{}` so older links and plan files still open) and go everywhere a plan goes. The built-in AI's conversation (`plan.chat`) stays in the browser. Typing a note (`editNote`) isn't undoable; accepting a suggested note or switch (`useNote`, `useSwap`) is.
- Claude never replays earlier turns as assistant messages in `/api/talk`: each question is one request with the transcript as data, so trimming or clearing a conversation can't break thinking-block rules. A suggested switch must be one of `swappable(brief)` (the schema is an enum), and the page recomputes its verdict with the rules before showing it.
- Lines are a custom `wire` edge that reads live node positions (`useInternalNode`) and finds its own ends (`src/components/wire.ts`), so nodes carry one hidden source and one hidden target handle. Labels are HTML buttons in `EdgeLabelRenderer` with `nodrag nopan`.
- The canvas always fills the window and never changes size when panels open, so React Flow never refits or warns. Panels, the bar, the dock and the Ask panel are absolutely positioned on top. Below 640px the side panels become sheets from the bottom, above the dock.
- The planner (describe, confirm) is a sheet over the canvas while `plan.step !== "plan"`; the dock and the summary only show once the plan is built.
- The first visit shows Connect before anything else (`stackwise.connect-seen` in localStorage); the default answerer is `stackwise.answerer`, shared by Connect, the pill, Ask and the description reader.
- A line replays its "connected" pulse and its label pops whenever what's at either end or its verdict changes: the flow path and the label are keyed by `data.signal`. A card replays its swap animation because its body is keyed by the option. No state or timers are involved.
- Removing a part the answers need empties it (`clearSlot`) instead of dropping it, and the toast says why; a part they don't need goes away (`autoPick`). Delete removes the selected part.
- Right-click menus are one list per target (`CanvasTarget` in PlanCanvas) built in `Workspace.openMenu`. Nodes, edge labels and the pane each call `onMenu`; edge labels are HTML buttons, so they need their own `onContextMenu`.
- On a canvas narrower than 560px, fitting stops at 45% zoom so cards stay readable; people pan for the rest.
- `/api/local` refuses anything outside the home folder, hidden and system folders, StackWise's own folder, and never replaces an existing `.env.local`. Michael's keys are his: StackWise writes names with empty values and says which names his file is missing.
- Never call `navigator.clipboard.readText()` from a Playwright evaluate: Chrome waits on a permission prompt and the tool hangs. Capture copied text by wrapping `writeText`.
- The Project panel never sees an env value. Names and "set or missing" come back; values go only from the page into the project's `.env.local` (created with mode 600), and from the file into a live check on this computer. Processes StackWise starts get a clean environment (PATH, HOME, JAVA_HOME and a few more), never StackWise's own, which holds its AI keys. Live checks are GETs only, and the SQL console runs one reading statement inside `BEGIN READ ONLY` with a 5 second timeout.
- Running processes live on `globalThis.__stackwiseRuns` so a hot reload doesn't lose them. They're killed as a process group, so a script's children (Maven, then Java) stop too.
- Ties between equally scored options follow `planning.json` `tie_order` (Next.js first for frameworks), then the alphabet. `data.test.ts` checks a plain web app still gets Next.js.
- Frameworks tie on every score (they're all free and portable), and ties break alphabetically, so adding a framework can change the default pick for every plan. Check `recommend` after adding one.
- A plan's app logo (`plan.icon`) is a small data URL kept in the browser like the layout, never in `SharedPlan`. The Project panel picks up the project's own icon (`findIcon`: the HTML's `<link rel=icon>`, then usual file names) or resizes one the person picks to 128px (`imageToIcon`).
- React Flow keeps a card's measurements (and so where its lines attach) only while it gets the same node object back. Nodes here are rebuilt whenever the plan or the selection changes, so `placed` puts each card's measured size (`sizes`, from `dimensions` changes) back on it. Without that every line on a rebuilt card has no ends for a frame and is unmounted and redrawn: that was the flashing during drags and on select. A MutationObserver on `.react-flow` during a drag should see zero added elements.
- During a drag only positions change: `placed` maps `dragged` over the nodes, so cards' data isn't rebuilt on every pointer move.
- Line labels show only the part's verb; the variables are in the tooltip (`detail`) and the connection panel. A light flows along every line that works (amber with a warning, none when broken), each starting at its own offset.
- "Tidy up" keeps the parts' clockwise order around the app and spaces them evenly (`arrangeInOrder`), so lines from the app can't cross, without undoing the person's arrangement.
- `#open=<absolute folder>` (what `stackwise` opens) picks the folder's `stackwise.plan.json`, else a plan whose folder matches (paths compared after expanding `~` with the home folder `/api/project` reports), else a new plan named after the folder with its README summary as the description and its detected framework pinned.
- A share link can carry a project folder: `#plan=<token>&folder=~/Projects/app` imports the plan and links the folder.
- Side panels are 380px (Details) and 360px (left), 330px under 900px. Anything new in Details or the palette needs to wrap; long URLs and env var names in the checklist use `overflow-wrap: anywhere`.
